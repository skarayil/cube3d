================================================================================
                       CUB3D PARSER ARCHITECTURE & NOTES
================================================================================

This document outlines the architecture, data models, call flows, validation
rules, memory layouts, and verification procedures for the Cube3D parser.

--------------------------------------------------------------------------------
1. PARSER EXECUTION FLOW
--------------------------------------------------------------------------------

The parsing phase runs fully before any graphics context or game logic begins.
The flow operates as follows:

   [argv[1]]
       │
       ▼
 1. main() (sources/main.c)
       │ Check file extension ends with '.cub'
       ▼
 2. ft_read_map() (sources/parsing/parser/read_file.c)
       │ Count lines via get_next_line(), allocate memory, and load lines
       ▼
 3. ft_parse_file() (sources/parsing/parser/parse_file.c)
       │
       ├─► ft_parse_identifiers() (parse_file.c)
       │     │ Loop lines to parse textures (NO, SO, WE, EA) & colors (F, C)
       │     ├─► ft_parse_texture() (parse_texture.c)
       │     └─► ft_parse_color() (parse_color.c)
       │
       ├─► ft_check_identifiers() (parse_file.c)
       │     │ Verify all textures & colors are initialized
       │
       ├─► ft_copy_map() (copy_map.c)
       │     │ Find map height, check for internal empty lines, copy/strip \n,\r
       │
       ├─► ft_check_map() (check_map.c)
       │     ├─► ft_check_map_chars() (check_map.c) -> Check invalid chars
       │     ├─► ft_check_map_closed() (check_walls.c) -> Adjacency border check
       │     └─► ft_check_player() (check_player.c) -> Exactly one player
       │
       └─► ft_init_player() (check_player.c)
             │ Locate player, set grid position, direction, and camera plane
             └─► ft_set_player_dir() (player_direction.c)

3. MEMORY OWNERSHIP DIAGRAM
--------------------------------------------------------------------------------

     [main] owns ──► `char **lines` (Free'd at end of main or on error)
       │
       ├─► Allocates `map.texture.north/south/west/east` via ft_strdup
       │     (Free'd via ft_free_map() at end of main / on error)
       │
       └─► Allocates `map.grid.data` (2D char array) via ft_copy_map()
             (Each row free'd, then double pointer free'd via ft_free_map())

--------------------------------------------------------------------------------
4. ERROR PROPAGATION FLOW
--------------------------------------------------------------------------------

Every function involved in parsing returns `bool` (or positive integers on
success and `-1`/`false` on errors). When any function returns `false`:
1. It prints an error message to `stderr` prefixed with "Error\n" using `ft_error()`.
2. The error cascades back up to `main()`.
3. `main()` calls `ft_free_lines()` and `ft_free_map()` to free all allocated
   structures up to that point.
4. `main()` exits with exit code `1`.

--------------------------------------------------------------------------------
5. PARSER VALIDATION RULES
--------------------------------------------------------------------------------

The parser strictly checks:
* Input file has '.cub' suffix.
* NO, SO, WE, EA paths are valid (end with '.xpm' after trimming spaces/tabs/CR).
* Color identifiers (F, C) contain exactly 3 integer channels between 0 and 255.
* No missing or duplicate configuration elements.
* No unknown configuration elements or identifiers before the map.
* Map must contain exactly one player character (N, S, E, or W).
* Map grid cannot contain invalid characters (only ' ', '0', '1', 'N', 'S', 'E', 'W').
* The map must be fully closed (walkable tiles '0', player start must not touch
  map boundaries or spaces ' ').
* The map must not contain empty lines inside the grid block.

6. SOURCE FILES & DOCUMENTATION
--------------------------------------------------------------------------------

================================================================================
FILE: sources/main.c
================================================================================
• Purpose: Entry point of the program. Coordinates file extension check, map
  reading, configuration parsing, data printing, and memory cleanup.
• Public Functions:
  - int main(int ac, char **av)
    - Description: Program controller.
    - Parameters: ac (argument count), av (argument array).
    - Return value: 0 on success, 1 on error.
    - Memory ownership: Owns map structs and the temporary lines array.
• Static Helpers:
  - static bool ft_check_extension(char *file)
    - Reason: Confirms file ends with `.cub`. Static to hide from other files.
    - Algorithm: Scans the end of the filename string.
  - static void ft_init_map(t_map *map)
    - Reason: Initializes structure members to safe values (-1 / NULL).
  - static void ft_free_lines(char **lines)
    - Reason: Safely frees 2D array of lines loaded from the file.
  - static void ft_free_map(t_map *map)
    - Reason: Safely frees texture paths and map grid strings.

================================================================================
FILE: sources/print_data.c
================================================================================
• Purpose: Display utility to write parsed map configuration details to stdout.
• Public Functions:
  - void ft_print_data(t_map *map, t_player *player)
    - Description: Prints game attributes and map grid.
    - Called by: main()
• Static Helpers:
  - static void ft_print_info(t_map *map, t_player *p)
    - Reason: Helper to print textures, floor/ceiling colors, and player vectors.

7. GENERATED STRESS & FUZZ TESTS
--------------------------------------------------------------------------------
A custom python test suite (`test_runner.py`) generates 109 distinct valid and
invalid test cases:
* Structural: Missing textures/colors, duplicate values, invalid spacing, completely
  empty files, only comments, wrong extension, multiple players, open maps.
* Extreme inputs: Carriage returns (`\r\n`), extra/trailing spaces, tab spacing,
  excessively long texture paths, large RGB overflows, multiple map definitions,
  fuzzed binary streams, and Unicode characters.
* Memory: AddressSanitizer and UndefinedBehaviorSanitizer integration verifies no
  overflows or leaks occur on any input.

--------------------------------------------------------------------------------
8. LIST OF BUGS FOUND & FIXED
--------------------------------------------------------------------------------
1. Signed Integer Overflow: `ft_atoi` had undefined behavior when parsing large
   numerical inputs (e.g. `9999999999999999999`). Fixed by checking value bounds
   and capping return values without losing correctness (since out-of-bounds RGB
   values are rejected anyway).
2. Carriage Return Failure: files using `\r\n` failed texture extension checking because
   `\r` was included in the parsed string. Fixed by trimming trailing carriage returns.
3. Long Line Spacing: long trailing whitespaces caused paths to not match `.xpm`. Fixed by
   trimming all trailing spaces/tabs.
4. Empty Lines in Map: empty lines inside maps were incorrectly parsed. Fixed by scanning
   and rejecting empty strings within the map boundaries.
5. Tab Separator Rejection: spaces inside config values were strictly checked as `' '`.
   Fixed by adding support for `\t` (tabs) in all configuration and token boundaries.
6. Dead Code: `find_map.c` contained functions that were never executed. Cleaned up
   and removed to minimize project footprint.
7. Memory Safety: fixed dangling pointer in `parse_texture.c` and potential leaks on
   read failure in `read_file.c`.

--------------------------------------------------------------------------------
9. CODE OPTIMIZATIONS & ARCHITECTURE IMPROVEMENTS
--------------------------------------------------------------------------------
* Removed `ft_rgb_to_int` helper function and replaced with an inline bounds check,
  saving a stack frame and keeping source files small.
* Standardized private functions to use static scopes, strictly keeping headers small.
* Added support for `\r\n` format, expanding compatibility to Windows-originated maps.
* Refactored RGB parsing to use a linear tokenizer validator rather than multiple loops.
